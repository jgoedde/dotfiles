## Components overview

- GNU stow to create symlinks to actual user directories
- Terminal: [ghostty](https://github.com/ghostty-org/ghostty)
- Shell: zsh
    - [Oh My Zsh](https://github.com/ohmyzsh/ohmyzsh) for theming and plugins
    - built-in `robbyrussell` theme (minimal prompt)
    - [`fzf`](https://github.com/junegunn/fzf) (fuzzy file utility)
    - [`bat`](https://github.com/sharkdp/bat) (better cat)
    - [`fastfetch`](https://github.com/fastfetch-cli/fastfetch) on launch
    - [`eza`](https://github.com/eza-community/eza) for a better `ls` with icons & colors
    - [`zoxide`](https://github.com/ajeetdsouza/zoxide) for smarter `cd`
- [pay-respects](https://github.com/iffse/pay-respects) funny little utility for the command line.
    - matugen themed: matugen only writes the `[colors]` layer to `~/.cache/matugen/xdg/`, added to `XDG_CONFIG_DIRS`; settings stay in the `pay-respects` stow package
- Launcher: DMS spotlight bar (`Ctrl+O`) with the [`webSearch`](https://github.com/devnullvoid/dms-web-search) and
  [`calculator`](https://github.com/rochacbruno/DankCalculator) launcher plugins, both without trigger prefix
    - search engines by keyword, e.g. `d <word>` (DWDS), `gh`, `y` (YouTube), `gm` (Google Maps), `deen`/`ende`/`dwrite` (DeepL);
      any other query offers Google and the other engines
    - typed URLs/domains (`fast.com`, `localhost:3000`) open directly in the default browser via the local `urlOpener`
      plugin, ranked above the other plugins (`launcherPluginOrder` in `settings.json`)
    - Firefox history via the local `firefoxHistory` plugin (`dms/.config/dms/plugins/firefoxHistory`,
      no trigger, refreshes every 2 min from a copy of `places.sqlite`; favicons cached in `~/.cache/dms-firefox-history`)
    - configured in `dms/.config/dms/plugin_settings.json`; plugins pinned in `plugins.lock.json`
      (restore with `dms plugins restore`)
- Compositor: [niri](https://github.com/YaLTeR/niri) with [DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell) (`dms`)
    - only hand-maintained files are tracked (`config.kdl`, `dms/binds.kdl`, `dms/windowrules.kdl`, dms `settings.json`);
      the other `niri/dms/*.kdl` includes (colors, layout, input, …) are regenerated by DMS
    - `xdg-desktop-portal/niri-portals.conf` routes file pickers to DMS Files (`dfiles`), gtk as fallback.
      Firefox only uses the portal picker with `widget.use-xdg-desktop-portal.file-picker = 1` (set in the profile's `user.js`)
- [matugen](https://github.com/InioX/matugen)
    - generates themes based on wallpaper (see below [Wallpapers](#how-wallpapers-work) section)
- git config for local ignores and aliases (`pull.rebase`, `push.autoSetupRemote`, `rerere`)
- [pywalfox](https://github.com/frewacom/pywalfox) to use the material colors in Firefox
- [`fd`](https://github.com/sharkdp/fd) for better `find`, also used as fzf source
- [btop](https://github.com/aristocratos/btop) and [micro](https://github.com/zyedidia/micro), both matugen themed
- [Material Bibata Cursor](https://github.com/SakibShahariar/material-bibata-cursor) - See [Cursors](#cursor)
- Claude Code settings + status line (via [`ccstatusline`](https://github.com/sirmalloc/ccstatusline))
- `.npmrc` with funding messages disabled

The zsh config is modular: `~/.zshrc` only sources `~/.config/zsh/*` in order. Machine-local overrides go into
`~/.config/zsh/custom/<same-filename>` or `~/.zshrc_custom`, not into the repo.

## Installation

```shell
git clone https://github.com/jgoedde/dotfiles ~/dotfiles
cd ~/dotfiles
./install.sh <profile>   # gnome or niri
```

The chosen profile is saved in `~/.config/dotfiles/profile`; later runs of `./install.sh` without an argument reuse it.

### Profiles

Packages are the top-level folders. A profile is a list of package names in `profiles/<name>.txt`, with an optional
setup script `profiles/<name>.sh` beside it.

- `common`: applied on every machine (shell, git, CLI tools, matugen, wallpaper, ghostty, ...)
- `gnome`: albert
- `niri`: niri, dms, dfiles

### What install.sh does

1. stows `common` plus the chosen profile with `--no-folding` (files are linked one by one, so nothing an app writes
   into `~/.config/<app>` lands in the repo)
2. runs `profiles/common.sh`: zsh plugin clones into `$ZSH_CUSTOM`
3. runs the profile's setup script, e.g. `profiles/niri.sh`: DMS plugin restore, dfiles service, `matugen-sync`

It does not download any other dependencies that are listed in Components section. Install them yourself.
The repo is expected at `~/dotfiles`.

Machines stowed before `--no-folding` still have whole directories linked into the repo (e.g. `~/.config/systemd`).
stow keeps those as they are. Unfold them once by unstowing everything and installing again:

```shell
cd ~/dotfiles
stow -D -t ~ $(cat profiles/*.txt)
./install.sh <profile>
```

### Desktop configuration

After installing ghostty, set it as default terminal.

```sh
gsettings set org.gnome.desktop.default-applications.terminal exec ghostty
```

## How Wallpapers work

Walls are expected to live in `<XDG pictures dir>/Walls` (e.g. `~/Pictures/Walls` or `~/Bilder/Walls`; override with
`WALLS_DIR`).
Pick a wallpaper in the DMS wallpaper browser (`Mod+Y`), or press `Mod+Ctrl+W` for a random one from the dir
(`wallpaper-change.sh`; it sets the wallpaper via DMS when it is running, otherwise via GNOME `gsettings`). Then,
`matugen-apply.sh` runs matugen (with its post hooks, which DMS's own matugen run skips) using the light/dark mode,
scheme and contrast currently set in DMS, to generate themes for following apps:

- bat
- obsidian
- pywalfox
- fzf
- btop
- micro
- ghostty (dark palette even in light mode; open windows reload via `USR2`)
- cursor (see [Cursor](#cursor))

On niri, the `matugen-sync.path` unit watches DMS's `session.json` and re-runs `matugen-apply.sh` when the wallpaper
or the light/dark mode changed since the last run (both are recorded in `~/.cache/matugen/last-apply`). Other session
changes are ignored. The Obsidian snippet holds both palettes (`.theme-dark` / `.theme-light`), so with Obsidian's
base color scheme set to "Adapt to system" it switches instantly.

GTK 3/4 colors come from DMS itself (`dank-colors.css`, enabled once via DMS settings → "Apply GTK colors").

An optional, untracked `~/.local/bin/wallpaper-post.sh` runs afterwards for machine-local steps, e.g. copying the
Obsidian snippet into a vault (see `wallpaper-post.example.sh`).

Machines set up before `matugen-sync` still run the old hourly timer. Remove it once, then reinstall:

```shell
systemctl --user disable --now wallpaper-change.timer matugen-mode-sync.path
rm -f ~/.config/systemd/user/{wallpaper-change.timer,wallpaper-change.service,matugen-mode-sync.path,matugen-mode-sync.service}
cd ~/dotfiles && ./install.sh <profile>
```

The generated color configs (bat, fzf, btop, micro, ghostty) are not tracked and are listed in
`.gitignore`. Run `matugen-apply.sh` once on a fresh clone to create them (without DMS, pass the wallpaper path:
`matugen-apply.sh <wallpaper>`).

## Cursor

Matugen is wired up with [Material Bibata Cursor](https://github.com/SakibShahariar/material-bibata-cursor). That setup
changes the cursor colors based on the wallpaper colors. It requires the cursor pack to live under `~/.icons`. One
directory in there for each cursor. Something like

```text
.icons
├── Bibata-Material-Apricot
├── Bibata-Material-Beige
├── Bibata-Material-Blush
├── Bibata-Material-Brown
├── Bibata-Material-Charcoal
├── ...etc
└── default
```

When Matugen is run, it detects the according pre-existing Material Design themed cursor and applies that for either
GNOME & GTK Applications, Hyprland compositor or XCursor fallback
